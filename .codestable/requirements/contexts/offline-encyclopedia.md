# 离线图鉴领域上下文

这个边界把活动内容包转换成可阅读的语义目录和图鉴条目，并管理跨内容包的本地收藏、历史和搜索连续性。

## 通用语言

**图鉴分类**：面向玩家的浏览入口，由应用内目录配置和活动包可用类型共同决定；它不是数据库的原始 `entity_type` 标签。

**图鉴条目**：供列表、搜索、详情、收藏和历史恢复使用的可读模型，至少包含稳定 ID、中文标题、可选英文标题、类型显示名、图片状态、摘要、事实分组和关系。

**稳定实体 ID**：`<entity_type>:<official-source-id>` 形式的跨页面和跨包键；不能只用数字源 ID。

**关系目标**：关系解析后的三种状态：可跳转的条目、可读文本、或“关联内容暂未收录”的不可用目标。

**村民支援记录**：数据包中的 `npc_schedule` 和 `villager_gift` 原始记录。它们保留在内容库中，但不是普通浏览条目；由对应 `villager` 条目聚合为日程和礼物偏好子菜单。日程键按游戏语义展示为春、夏、秋、冬四组及其日期覆盖（如 `spring_4`），季节无关日期、天气、节日和婚后规则另列；不能把每条原始记录当成无日期的普通日程。

**个人记录**：Room 中的收藏、浏览历史和最近搜索。收藏与历史通过稳定实体 ID、搜索通过标准化查询键与应用状态关联。

**购买价**：从商店取得物品时支付的金币报价；它属于商店及其适用条件，不是物品固有属性。以物品或特殊货币交换时称为**兑换成本**。玩家卖出物品获得的金币称为**出售价格**；“基础价格”只用于确有计算基准的语境。

**获得方式**：玩家如何取得实体的总称，包括购买来源、制作获得、怪物掉落、宝箱奖励、任务奖励和采集地点等。**用途**说明实体可以做什么；**制作材料**与**用于制作**分别表示配方的消耗方向和材料的反向用途。

**地点**：玩家能辨认并前往的命名区域。钓鱼环境称为**水域**；单个矿井楼层称为**矿井层数**，连续范围称为**矿井层段**；较大的生成范围称为**出现区域**。原始地点 ID、区域 ID 和生成参数不自动等同于这些玩家概念。

**制作条件**：制作材料、数量、配方来源和解锁要求。机器输入、产出和耗时称为**加工规则**。**升级条件**包含前一级、材料、购买价、办理地点和解锁要求；升级耗时与升级效果分别表达。“合成条件”不作为制作、加工和升级的混合泛称。

**固定信息**：不依赖玩家状态即可成立。**适用条件**是会改变结论的季节、天气、年份、任务等限制。**动态信息**依赖日期、进度或存档，应用只说明规则，不宣称当前结果。**未知**表示官方证据不足，**暂未收录**表示当前数据包尚未提供可能存在的证据，**不适用**表示概念对实体没有意义；三者不等同于不存在、`false`、`0` 或空值。

**人物关系**：使用亲属关系、朋友关系、亲友关联、监护关系、同住关系和角色配对指针的闭集。亲友关联表示官方只确认某人属于 `FriendsAndFamily` 而未注明具体类型；角色配对指针对应 `LoveInterest`，不是正在恋爱。可婚配资格是人物属性，不是人物关系。

## 稳定规则

- 图鉴按玩家行动组织信息，不按数据库字段是否存在组织。分类列表只显示图片、名称和最多两组能区分同类条目的行动摘要；详情首屏回答该类别的核心行动问题，深入机制和少见例外进入次级区。核心答案缺失时显示未知或暂未收录，不用类别名、记录数、原始枚举、规则数量或相似技术参数填充。
- 八类玩家信息契约是：商店先回答地点、营业/出现规则、商品报价与条件；作物先回答季节、成熟、种子获得与成本、收获/再生/关键要求和出售价格；村民先回答常住地、日程规则、生日、最爱礼物、婚配资格和有依据的关系；大型可制作物先回答用途、制作或其他获得方式、加工与放置规则，并区分加工机器、功能设施/容器、装饰/照明和不可制作物；工具先回答用途、档位、升级条件、耗时与效果；怪物先回答出现区域/矿井层段、掉落、生命/攻击和自然语言战斗特征；鱼类先回答水域/地点、季节/时间/天气/条件和出售价格；武器先回答获得方式与具体地点/层数、伤害/类型及购买或出售价格。当前包缺少这些核心事实时保留“暂未收录”，不能用 `SalePrice`、`MineBaseLevel` 或 AI 参数冒充答案。
- `WikiCatalogue` 是页面的内容边界。首页、分类、搜索、详情、收藏和历史使用它的模型，不直接读取 `ContentDatabase`、原始 JSON 或技术类型 ID。
- 首页只保留快捷入口与“全部分类”四列网格：每个活动包中有数据的可浏览类型各有一个直接入口，并按农场经营、人物与社区、探索与战斗、任务与收集、料理与制作等小分组标题组织；未知未来类型进入“其他资料”。这些标题只组织全部分类，不是可点击的大类导航。`npc_schedule` 与 `villager_gift` 是村民支援记录，不作为普通类型入口或搜索结果单独出现；它们由对应村民条目聚合为可展开子菜单。普通界面始终使用 manifest 的可读 `displayName`，不把原始 ID 当标题。
- 分类页只使用四列网格展示轻量摘要、可选英文名和必要类型信息，不提供布局切换或重复的结果统计；保留分类内搜索和筛选。作物筛选固定按春、夏、秋、冬展示，跨季作物进入每个适用季节；商店分为普通商店和节日商店；村民提供全部村民、不可结婚村民、可结婚女性村民和可结婚男性村民。季节和可婚配筛选只读取 `officialDerived` 已确认字段，未知值只保留在全部结果中。搜索框用占位提示而非浮动标签，避免聚焦时的轮廓缺口。没有图片的条目使用与类型匹配的图标和色块，而非首字母占位。详情页以高密度的头部摘要、两列事实、可展开子菜单和关联内容组织信息，摘要正文不可无入口截断。村民详情继续把日程和礼物偏好作为可展开信息区。详情由 `DetailPresentationParser` 按实体类型读取已确认字段和 `officialDerived`。缺失字段不推断为 `false`、`0` 或永不发生；未知字段不强行解释，游戏条件只原样说明而不求值。
- 人物关系保留官方记录方向，不自动镜像；只有双方均有记录或经过真实官方数据验证的互逆称谓规则时才生成明确反向称谓。`Home` 只表示人物到地点的条件化住所，相同住所、年龄、日程或共同事件不能推导同住、亲属、朋友或监护。应用不读存档，因此不显示玩家与人物当前的恋爱、订婚或婚姻状态。文森特与贾斯在当前官方数据中只显示“亲友关联（具体关系未注明）”，不显示恋爱对象，也不在没有额外获准证据时写成好朋友。
- 关系解析集中在 `EntityRelationResolver`，先生成候选稳定 ID 再批量查询。无法唯一跳转时，普通关系保留可读信息或显示明确未收录状态；商店商品关系只保留能解析为已发布条目的商品，未收录的运行时/动态选项直接隐藏，不创建假实体、不向普通页面泄漏原始 ID。商店的 `Owners[].Id` 只有解析为已发布的 `villager` 条目时才作为店主，分类卡优先展示该村民头像；没有可解析店主时按已确认的商店性质展示语义图标，不能把 `AnyOrNone`、关闭状态等运行时值伪装成人物。商店详情可展示已确认的商品数、交易货币和可跳转店主。
- 搜索先标准化输入，再合并中文/英文前缀、别名、拼音、首字母和 FTS 命中；按实体 ID 去重并保留最高分和命中原因。已选实体类型会下推到每种 SQLite 查询，页面保留当前包完整的类型筛选入口。查询参数必须绑定，用户输入中的 LIKE/FTS 特殊字符不能改变查询语义。
- 图片只从活动包的 `image_path` 解析本地文件；路径越界或文件不存在时使用明确的本地占位，不联网、不现场裁切游戏图集。
- 收藏、历史和搜索历史不写内容库。数据包更新后保留稳定 ID 记录；当前包不存在的收藏/历史仍可见并可删除，搜索历史的连续性不依赖当前实体存在。
- 村民日程只展示包含有效时间和地点的记录；坐标、日程条件及 MAIL/GOTO 等技术指令不进入日程阅读模型，界面按时间顺序纵向排列多组“时间 / 地点”两列，组间可用向下箭头连接，日期/季节仅作为分组上下文。
- 主导航是首页、搜索、收藏、更多；数据管理从“更多”进入。最近浏览显示在搜索页的空搜索状态，不再作为首页内容块。详情 ID 进入 Navigation 前必须 URI 编码。

## 代码锚点

- `data/wiki/WikiCatalogue.kt`：目录配置、条目模型、搜索适配和关系降级。
- `core/model/WikiCatalogueModels.kt`：图鉴分类、条目、关系目标和图片状态。
- `core/database/content/ContentDatabase.kt`、`data/SearchRepository.kt`：摘要批量投影、实体类型筛选、别名、拼音和 FTS 查询及分层评分。
- `core/json/DetailPresentationParser.kt` 及其 `DetailFactParser`、`DetailRelationParser` 内部模块，配合 `core/formatter/DetailFormatters.kt`：类型事实、关系、条件和数值的可读表达。
- `data/EntityRelationResolver.kt`：稳定 ID 候选与批量关系解析。
- `core/database/user/UserDatabase.kt`、`UserDataDao.kt`、`data/UserDataRepository.kt`：本地个人记录和软引用。
- `feature/home/HomeFeature.kt`、`feature/type/TypeListFeature.kt`、`feature/search/SearchFeature.kt`、`feature/detail/DetailScreen.kt`、`feature/favorites/FavoritesFeature.kt`、`feature/history/HistoryFeature.kt`：用户路径。
