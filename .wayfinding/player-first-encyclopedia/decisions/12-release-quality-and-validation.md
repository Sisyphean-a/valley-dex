# 发布质量与真实数据验收

## 问题

两个仓库的发布门禁和真实数据验收必须证明哪些语义覆盖、图片质量、玩家任务和跨仓库兼容结果，才能把“可构建”提升为“玩家真正可用”？

## 答案

### 验收原则

发布质量分为四类，不能相互抵消：

1. **绝对正确性门禁**：发现一例即停止发布；
2. **逐分类、逐核心槽覆盖门槛**：衡量玩家问题实际可回答程度；
3. **相对上个获准真实包的回归门禁**：防止总体平均掩盖局部退化；
4. **真实包、真实设备和玩家任务证据**：证明跨仓库产物确实可用。

fixture 和代码生成的模拟官方目录只证明边界与拒绝路径，不能替代真实游戏资产构建、真实 schema 5 包安装和真实玩家任务验收。当前 schema 4 `dist` 只作为迁移基线，不是 v5 发布证明。

### 绝对正确性门禁

以下项目必须 100% 通过，任一错误均阻断 `.svdata` 或 App 激活：

- manifest 2、schema 5、`player-facts-v1`、schema 指纹、`PRAGMA user_version`、必需索引、`quick_check`、`foreign_key_check`、数据库/图片/报告哈希与元数据一致；
- 每个分类契约核心问题恰有一个事实槽，状态、类型化值、条件和证据组合合法；
- 每个已知事实与关系有可定位来源；派生事实有输入证据和可复现转换规则；
- 条件子句没有静默丢失，partial/opaque 条件不冒充 fixed；
- 关系目标、方向和经过验证的互逆规则有效，不自动补无证据反向事实；
- `entity_cards`、搜索词和 `browse_facets` 可由规范事实逐行重建，且同一报价、捕获、出现或获得规则的 facet 不跨 scope 拼接；
- 所有实体具有合法视觉状态，必需名单图片物化率 100%；解码失败、全透明、非法裁切、哈希不符、来源碰撞、通用占位图片和 `pending_review` 均为 0；
- 补充事实无过期、冲突、来源缺失或冒充官方；
- App 合成坏包拒绝矩阵全部通过，任何验证失败保持原活动包且不向业务查询暴露半迁移内容。

### 核心事实覆盖门槛

统一分母和指标：

- `eligible = 实体总数 - not_applicable`；
- `answered = fixed + conditional + dynamic_rule`；
- `investigated = answered + unknown`；
- `pipeline_gap = not_collected`；
- `answered_rate = answered / eligible`；
- `not_collected_rate = not_collected / eligible`。

门槛按“分类 × 核心槽”分别计算，不能用全局平均抵消最差类别：

| 层级 | answered_rate | not_collected_rate |
|---|---:|---:|
| P0：地点、时间、价格、获得方式、材料等直接阻断行动的槽 | ≥95% | ≤2% |
| P1：其他分类核心槽 | ≥85% | ≤10% |
| 已确认存在稳定官方直接字段的槽 | 100% | 0% |
| 人物关系组 | ≥90% | ≤5% |
| 条件完整性 | complete ≥95% | opaque ≤1% |
| 可浏览实体名称索引、唯一卡片、facet group | 100% | 0% |

`unknown` 表示已调查但未回答，不计 answered；补充事实不设最低占比，避免为提高数字而滥加非官方数据。一等 facet 对所有已知且有可靠静态范围的适用事实投影率必须为 100%，非名称搜索词必须 100% 可追溯到规范事实。

### 回归预算

每个候选包与上一个获准真实包比较实体、事实槽及状态、关系、搜索词、facet、视觉状态、规则和图片哈希：

- 任意未解释删除或状态退化阻断发布；
- `fixed/conditional → unknown/not_collected` 以及 `unknown → not_collected` 均为退化；
- 任一“分类 × 核心槽”回答率下降超过 1 个百分点，即使仍达最低门槛，也必须人工批准；
- not_collected 率增加超过 0.5 个百分点必须人工批准；
- 游戏版本变化导致的合理差异逐组说明，不能用总量增长抵消局部退化；
- 首个 v5 与冻结真实 v4 包执行迁移差异审计，但不要求旧 JSON 与新类型化语义逐字段相等；首个获准 v5 成为之后的比较基线。

### 图片人工复核

每个真实候选包必须复核：

- 所有新增或内容哈希变化图片；
- 所有来源、裁切、复用或视觉规则变化图片；
- 所有自动异常候选；
- 每个玩家可浏览分类至少 5 张固定代表图；
- 其余未变化图片按分类抽查 5%，每类至少 3 张、至多 20 张。

游戏版本未变且输入、规则、哈希完全一致时可复用上次逐图结论，但仍执行固定代表样本抽查。一个具名审核者完成全部必审范围；错实体、来源碰撞、异常复用或判断有歧义时必须第二人复核。自动检查不能代替人工视觉判断，`pending_review` 必须为 0。

### App 自动与真实设备矩阵

自动 CI 至少覆盖：

- API 26、30、36；
- 320dp、360dp、411dp 手机及至少 600dp 平板；
- fontScale 1.0、1.3、2.0；
- 浅色与深色；
- schema 5 合成坏包拒绝矩阵；
- 一个由真实官方资产构建的真实 schema 5 包安装、查询、验证、切换和回滚流程。

每次发布候选还需真实设备验证：

- 一台接近最低能力的 API 26–30 手机；
- 一台当前 API 普通手机；
- 一台平板或大屏设备；
- 至少一台开启 TalkBack，执行搜索、筛选、详情展开和返回。

暂缺三台实体设备时，可用一台实体手机加两个仿真设备临时完成，但发布证明必须明确设备性质，不能称为全真实设备覆盖。

### 玩家任务验收

以下任务全部成功且错误答案数为 0：

- 找到春季可种且成熟较快的作物；
- 找到河流、春季、雨天可钓的鱼，并确认条件来自同一捕获规则；
- 按地点找商店并区分金币购买与物品兑换；
- 从木材反查需要它的制作内容；
- 从掉落物反查来源怪物及出现区域/矿井层段；
- 查看工具完整升级链；
- 按伤害与获得方式查找武器；
- 查看文森特和贾斯关系且不产生恋爱或自动镜像结论；
- 验证 unknown、not_collected、dynamic_rule 和 partial 条件不会变成固定结论；
- 验证官方无图、代理视觉、包缺图和解码失败互不混淆。

每项至少覆盖正常、缺失/条件化和无结果恢复场景；稳定自动断言与真实候选包人工执行都必须通过。另验证同维度 OR、跨维度 AND、同 scope 联合条件、稳定分页无重复/遗漏、切包游标失效、加载时查询快照不与旧结果错配。

### 性能与查询计划 SLO

在固定普通参考设备、固定真实包和固定测试版本上：

- 热缓存列表、搜索、facet 查询 p95 ≤100ms；
- 详情核心事实和反向关系查询 p95 ≤50ms；
- 冷启动后首次内容查询 p95 ≤300ms；
- 真实包导入、解压和完整验证 p95 ≤30s；
- 活动包正常冷启动到可交互 p95 ≤2s；
- 关键浏览流程卡顿帧比例 ≤5%，不得出现超过 700ms 的冻结帧；
- 分页全遍历无重复、遗漏或固定候选截断；
- 大表查询不得出现未批准全表 `SCAN` 或大结果 `USE TEMP B-TREE`，小型枚举表例外必须白名单记录。

硬件或真实包规模变化时重新记录基线，不能直接把不可比结果解释为回归或改善。

### 发布证据及保留

每个发布候选形成内容绑定的证据集，至少包括：

- `release-attestation`：版本、输入 hash、门禁结果、设备、审核与审批；
- schema/外键/索引/包完整性结果；
- 逐分类逐核心槽覆盖和失败实体；
- 条件、证据、关系、补充事实审计；
- 搜索/facet 重建、查询计划、分页和玩家任务结果；
- 图片清单、确定性联系表、异常与人工复核结论；
- v4→v5 或 v5→v5 差异报告；
- App 安装、拒绝、回滚、无障碍、设备和性能结果。

当前发布和前两个发布的完整证据始终保留；完整证据至少保留 12 个月，两者取更长。精简的发布版本、输入 hash、审批者、门禁摘要和最终结论长期保留。真实游戏资产和图片不得写入 Git；仓库只保留可公开的规则/模板，真实证据在工作区外保存哈希、定位、统计和报告。

### 阻断、人工批准与警告

- 绝对正确性失败、最低覆盖失败、未处理图片、错误玩家答案、真实包安装/回滚失败或 SLO 失败均阻断发布；
- 在最低门槛之上但超过回归预算的已解释变化，需要具名人工批准并进入 release attestation；
- 设备临时替代、性能基线不可比及未达到更高改进目标可以作为显式警告，但不能掩盖硬门禁失败；
- 不得通过改分母、把 unknown 改 not_applicable、关闭 imageRequired、减少样本或删除失败实体来提高指标。分母、资格和状态变化本身进入差异审计。

### 范围边界

本项确定发布门槛、阈值、证据和真实验收职责，不实施测试框架、CI 或发布命令。具体跨仓库实施顺序归决策 13。

## 依据

- 用户在 2026-08-13 接受绝对门禁、覆盖阈值、回归预算、图片复核、设备矩阵、玩家任务、性能 SLO 和证据保留八组规则。
- 当前 builder `quality.py` 主要检查翻译、数据错误和类型标签；`build_coverage` 只统计分类总量、是否存在任意 `officialDerived` 和全局 `imageRequired`，可能由无关字段、改变分母或总体平均掩盖核心缺口。
- 当前 `tests/test_real_official_data.py` 使用 `create_real_layout` 生成模拟目录，证明解析边界但不证明真实官方资产；当前真实 v4 `dist` 的 3625 个实体和旧图片 1031/1031 只能冻结为迁移基线。
- 当前 App 合成包仍是 schema 4，现有真实包任务只验证安装边界；缺少 schema 5 的事实槽、状态、证据、关系、facet、图片状态和玩家任务拒绝矩阵。
