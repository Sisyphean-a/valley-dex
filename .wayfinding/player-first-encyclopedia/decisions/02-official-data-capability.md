# 官方数据能力矩阵

## 问题

对玩家核心问题，官方资产中哪些事实已经被 builder 正确提取、哪些只存在于原始源或跨实体关系、哪些需要运行时规则分析、哪些确实无法从当前官方来源可靠得到？

## 答案

### 证据等级

- **A｜链路完整**：官方源语义明确，builder 已规范化，schema 4 已发布，应用已有正确消费入口，并有对应测试或真实布局证据。
- **B｜官方事实可达但链路未闭合**：官方字段、原始记录或跨实体关系存在，但尚未规范化、反向挂载、统一命名或被应用正确消费。
- **C｜必须解释条件或运行时规则**：静态包能保存规则或候选事实，但不能在不读取日期、天气、进度、事件、存档或游戏逻辑的情况下给出当前结论。
- **D｜静态官方包不能可靠回答**：问题本身询问玩家当前状态或攻略式判断，超出静态官方事实能力。
- **E｜证据不足**：当前未加载、未识别或未测试；只能继续调查，不能写成“官方源没有”。

### 能力矩阵

| 类别 | A：当前可靠能力 | B：官方事实存在但链路断裂 | C：需条件/运行时分析 | D/E：不可静态回答或仍待调查 |
|---|---|---|---|---|
| 商店 | 固定商品、基础报价、货币、兑换物、库存字段、店主 ID 和条件表达式已进入 `shopOffers` | 没有统一商店地点、营业时间和闭店例外；应用未完整消费商品条件、价格修正与库存规则 | “此时是否可买”、最终价格、随机商品、节日/进度可用性 | **D**：今天是否营业、此刻价格/库存；**E**：地点和营业规则可能散落在世界地图、事件或运行时入口，当前未识别资产不能证明不存在 |
| 作物 | 季节、生长阶段/总天数、再生、浇水、水田、棚架、种子、收获物、种子商店报价；收获物基础售价可跨到 Object | 售价未直接挂在 crop；特殊种植地点、收获工具、完整种子非商店来源尚未形成玩家语义 | 商店条件、`PlantableLocationRules`、职业/品质/肥料收益和特定日期可种性 | **D**：不带玩家状态的最终收益与某日实际可买性；特殊地点规则仍属 B/C 而非“没有” |
| 村民 | 生日、粗粒度居住区、性别、可婚配资格、礼物偏好和原始日程已可达 | `Home`、`FriendsAndFamily`、`LoveInterest` 未形成有类型的实体关系；住所和同住未规范化 | 某日日程选择依赖季节、日期、天气、节日、邮件、事件、友谊和婚后状态；监护/同住只有明确标签时才能成立 | **D**：当前所在位置、玩家实际恋爱或配偶；**E**：官方关系值结构能稳定支持哪些亲属/朋友标签尚需逐项核验 |
| 大型可制作物 | 大型物实体和图片可发布；制作配方能规范化材料、数量和产物；机器规则保留输入、输出、数量和耗时 | 配方没有按产物反向挂回大型物；配方来源/解锁仍在原始槽位；机器规则挂在输入物品上，机器详情不能直接回答完整用途 | 标签触发、条件产出、特殊输出方法和放置条件 | **E**：不可制作物的完整获得来源、每台机器全部输入输出与解锁覆盖尚无专项真实包证明 |
| 工具 | 工具实体、类型、升级档位、`UpgradeFrom`/`ConventionalUpgradeFrom` 等原始字段可保留 | 没有工具专属派生；前一级未形成关系；升级材料、支付价格、地点、耗时和效果没有稳定闭环；`SalePrice` 只能作出售价格 | 升级服务、时间推进、进度条件及实际效果由游戏逻辑决定 | **E**：动态 `TOOL_UPGRADES`、商店升级服务和效果数据能否从现有官方资产完整重建；当前不能断言官方源没有 |
| 怪物 | 旧格式生命/攻击等数值可达；基础掉落已拆成 `drop` 实体并保留概率 | 怪物没有专属派生；战斗数值仍是 legacy 槽位；无出现区域/矿井层关系 | 刷怪、矿井楼层生成、危险状态/变体和掉落修正 | **D**：仅从数值可靠生成攻略式打法文案；**E**：出现区域/层段的官方规则来源尚未加载，不能从怪物字段推断 |
| 鱼类 | 时间窗、季节、天气；`Locations` 中地点、区域、概率、钓鱼等级、离岸距离；鱼塘规则与产物 | 没有统一海/河/湖水域类别；基础售价需跨到 Object；地点 ID 尚未完全玩家化 | 地点条件、鱼塘产物条件、魔法鱼饵等运行时修正 | **D**：不带状态的当前可钓性；水域类别属于可规范化的 B，不是官方事实缺失 |
| 武器 | 静态商店获取、基础报价/兑换；武器原始伤害、类型和属性可达 | 无武器专属派生；售价语义无专项测试；怪物掉落、奖励和来源没有统一反向聚合 | 宝箱、矿井/火山生成、事件奖励和条件价格；`MineBaseLevel` 仅是生成参数候选 | **D**：把 `MineBaseLevel` 直接说成实际获取层；**E**：宝箱、奖励和完整层段来源尚未纳入支持资产 |
| 图片 | 官方图片源、fallback、裁切矩形/sprite、WebP 物化、路径、缺失/越界/全透明错误及数量报告链路完整 | 个别纹理复用依赖显式视觉规则 | 不适用 | **E**：自动门禁只证明文件存在、可解码、非全透明和裁切合法，不能证明每张图片主体正确、肉眼可辨 |

### 跨类型结论

- 当前没有统一的 **购买价**：购买是某商店在某条件下的报价 `shopOffers[].price`，不是实体固有属性。
- 当前没有统一的 **出售价格**：`sellPrice` 只规范化到 object/mineral/ring；鱼需跨实体，武器、工具和大型物仍使用各自原始字段或没有已验证语义。
- 当前没有统一的 **获得方式**：商店、配方、机器、掉落、奖励和宝箱分散在不同实体或支持表，且多数没有反向聚合。
- 静态包可以发布“规则与条件”，但不能宣称玩家此刻满足条件。未知条件不能被格式化器静默删除后伪装成完整结论。
- `schema 4` 技术上能通过 `extra_json` 携带这些数据，但“能装进去”不等于已形成稳定的玩家语义契约。

### 必须保留的未知

- `FestivalDates.json`、`LocationContexts.json`、`mail.json`、`Events/Mine.json`、`TriggerActions.json`、`WorldMap.json` 等在真实报告中仍是未识别资产；它们可能含地点、事件、奖励或可用性证据。
- 工具升级、怪物楼层、武器宝箱/奖励、商店地点/营业规则均需进一步调查游戏规则和未识别资产，不能在后续设计中当作已确认缺失。
- 图片的视觉正确性必须由后续图片质量门槛解决，不能由数量完整性代替。

## 依据

### builder 链路

- `src/builder/sources/official_support.py:9-35`：当前只加载 `FishPondData`、`Locations`、`Machines`、`Shops` 四类支持资产。
- `src/builder/pipeline/official_enrichment.py:25-180`：当前专属派生仅覆盖 crop、fish、villager、recipe、object/mineral/ring；tool、monster、weapon、big_craftable 没有专属派生。
- `src/builder/pipeline/official_references.py:29-208`：鱼地点/鱼塘、机器输入、商店报价和配方原料反向用途；尚无地点通用模型、产物到配方反向关系或统一 acquisition。
- `src/builder/pipeline/official_shop_references.py:9-67`：基础价格、货币、交换物、库存、条件和价格修正的静态报价。
- `src/builder/pipeline/images.py`、`commands/build_output.py`：图片物化、边界/透明检查、错误和数量报告。
- `src/builder/database/schema.sql`、`database/writer.py`：schema 4 通过 `entities.extra_json` 原样承载 `officialDerived`，没有结构化领域列。
- `tests/test_real_official_data.py:115-140,239-311`：真实官方布局覆盖大型物入库/图片、作物生长与售价、鱼地点、商店关联；尚缺工具、武器来源、大型物配方反向、兑换等专项断言。

### 应用消费

- `core/json/DetailFactParser.kt`：仍直接解释 tool/monster/weapon/big_craftable 原始字段；部分字段名被过早当作玩家事实。
- `core/json/DetailRelationParser.kt:38-156,349-365`：消费种子来源、鱼地点、商店报价和掉落，但商品条件/修正消费不完整，人物关系只有 `loveInterest`。
- `data/wiki/VillagerSupportPresentation.kt`：日程阅读主动移除了条件和技术指令，所以只能展示候选记录，不能选择“某日实际日程”。
- `data/wiki/WikiCatalogue.kt`：页面边界尚无统一购买价、售价、获得方式和地点模型。

### 调查方法与记忆处理

四个并行只读视角分别审查商店/作物/配方/工具，人物/怪物/武器，鱼类/图片/跨类型链路，以及跨仓库对抗审查。结论只基于当前代码、真实布局测试和现有报告；本轮未运行真实游戏完整构建。

本答案是后续领域词汇、缺口策略和数据契约的调查依据，尚未形成最终稳定契约，因此暂不写入两个仓库的 `.codestable`；待相应裁决闭合后由 `cs-domain` 分别更新其唯一当前态。
