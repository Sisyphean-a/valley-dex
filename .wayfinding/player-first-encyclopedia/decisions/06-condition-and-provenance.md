# 条件与来源可信度

## 问题

数据包和应用应如何统一表达固定、条件化、动态、未知、不适用及其事实来源，使价格、库存、时间、地点、掉落和获得方式不会被误读成无条件结论？

## 答案

### 事实状态

每条玩家事实和关系必须明确属于以下状态之一：

- **固定信息**：不依赖玩家状态即可成立。
- **条件信息**：结论成立，但必须同时满足所附适用条件。
- **动态规则**：只能发布规则；需要当前日期、进度或存档才能求值，应用不得宣称当前结果。
- **未知**：已经调查相关证据，但证据不足、冲突或无法可靠解释。
- **暂未收录**：证据可能存在，但当前资产、解析器或关系链尚未纳入产物。
- **不适用**：分类契约明确该问题对该实体没有意义。
- **拒绝发布**：内部准入状态；来源、条件或推导不能通过校验时不进入发布事实。

`null`、空字符串、空数组、`false`、`0` 和 `-1` 都不能自动映射为未知、暂未收录或不适用；状态必须由字段契约和证据决定。

### 事实级来源

实体级来源文件集合不足以证明单条事实。每条核心事实和关系必须可追踪到：

- 主体实体和字段或关系路径；
- 事实状态；
- 来源类别、游戏版本、来源文件及记录定位；
- 原始条件和条件完整性；
- 跨表关联或计算的输入事实与可复现转换规则；
- 本地展示覆盖的目标字段；
- 证据是否完整、可验证或存在解析问题。

来源类别必须区分：

1. **官方直接字段**；
2. **官方跨表关联**；
3. **可验证计算**；
4. **本地展示覆盖**；
5. **Wiki 语义参考**。

官方跨表关联和可验证计算可以形成可靠玩家事实，但不得标成“官方原文”或“官方结论”。中文 Wiki 只用于理解玩家问题、中文术语、分类和信息优先级；它不能进入游戏事实证据链，也不能提高事实可信等级。

### 条件完整性

- 完整可解释的条件转成玩家语言，并紧邻其所限制的价格、库存、时间、地点、掉落或获得方式展示。
- 部分可解释的条件同时展示已解释部分和“另有未识别条件，需在游戏中确认”。
- 完全不识别的条件保留原文供诊断，普通页面只显示“受游戏条件限制（需在游戏中判断）”。
- 未识别子句不得静默丢弃；部分解析或不透明条件不能升级为固定信息，也不能参与“当前可买”“当前可钓”“当前出现”等布尔筛选。
- 当前范围不产生“当前已满足条件”的求值结果；未来若引入存档或运行上下文，必须另行决定求值上下文与时间证据。

### 玩家展示

- 普通固定事实默认直接显示，不用来源徽章淹没主要信息。
- 条件、动态、未知和暂未收录必须在答案旁直接说明状态或限制；不适用只在玩家需要区分时展示。
- 派生事实必要时标明“依据游戏数据整理”或“依据游戏数据计算”，不能伪装成官方原文。
- 完整文件路径、记录定位、转换规则、原始条件和覆盖记录进入可展开的数据说明或诊断层，不进入默认首屏。
- 本地展示覆盖只能改变获准的名称、摘要、别名等展示字段；改变事实含义或写入官方派生区域的覆盖拒绝发布。

### 发布门禁

- 分类契约中的核心事实只要发布了值，就必须同时具备事实状态和事实级来源。
- 条件化核心事实丢失条件、静默丢失未知子句或被降为固定信息时阻止发布。
- 人工覆盖不得写入官方派生区域冒充官方来源或派生。
- 未知和暂未收录可以发布，但必须明确标记并进入覆盖报告；它们不是数据错误的成功替代品。
- 来源不可定位、推导不可复现、状态互相矛盾或关键关系方向不明时，相关事实拒绝发布；是否阻断整个数据包由后续发布质量决定按核心契约裁决。

本决定只确立语义、不变量和准入要求；具体 schema、DTO、版本迁移、诊断 UI 和包级阻断阈值留给决策 09、10 与 12。

### 语义所有权

- `stardew-offline-data-builder` 的 `context:offline-official-data` 拥有事实状态、条件完整性、事实级来源和派生可复现性的产出语义。
- `valley-dex` 的 `context:offline-encyclopedia` 拥有这些状态和来源在玩家页面的表达，并且不得丢失或重新猜测 builder 提供的限制。

## 依据

- 用户在 2026-08-13 对事实状态闭集、事实级来源、条件完整性、玩家展示和发布门禁确认“全部接受”。
- 当前 builder 的 `_provenance` 按实体合并来源文件；`official_enrichment.py` 把跨表来源继续并入同一集合，无法区分直接字段、跨表关联、计算和手工覆盖的单条归属。
- 当前 builder 的商店报价保留 `condition`、`perItemCondition`、价格修正和库存规则，但应用 `DetailRelationParser.offerDetails` 只展示购买价格，会把条件化报价误读为固定结论。
- 当前应用 `DetailFormatters.condition` 对条件子句使用 `mapNotNull`；只要存在一个已识别子句，其他未知子句会静默消失。
- 当前 `DetailFact` 与 `WikiEntry` 没有事实状态、来源或条件完整性，因此不能区分未知、暂未收录和不适用。
- 当前 builder 质量门禁主要检查翻译、类型标签和上游数据错误，尚不能证明核心事实的来源与条件完整。
