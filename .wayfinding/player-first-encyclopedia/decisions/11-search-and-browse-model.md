# 搜索与浏览模型

## 问题

除名称搜索外，哪些地点、季节、时间、价格、来源、材料需求和关系应成为一等搜索、筛选或反向浏览入口，且各入口怎样避免重复与信息过载？

## 答案

### 总体模型

搜索、筛选和反向浏览分工如下：

- **全局搜索**负责找到已知名称或少量受控玩家语义；
- **分类筛选**负责在同类条目中按小而稳定的维度缩小范围；
- **反向浏览**负责材料、商品、掉落、机器输入输出和人物关系等高基数、有方向的关联；
- 三者都读取 `player-facts-v1` 的规范事实、关系、`entity_cards` 和 `browse_facets`，不能解析详情 JSON 或形成第二事实源。

公共查询模型至少表达：全局或分类 scope、可选文本、分组 facet 选择、排序、游标和页大小；反向浏览另表达锚点实体、关系族、方向、目标类型、游标和页大小。

### 全局搜索

直接条目结果索引：

- 中文名、英文名、别名、拼音和拼音首字母；
- 经 builder 审核生成的地点、水域、用途、获得方式和自然语言类别搜索词；
- 不索引原始 ID、枚举、条件表达式、诊断文本或无法证明的推断。

名称精确、名称前缀和别名命中优先于玩家语义命中。每个非名称命中给出可读原因，例如“匹配：河流 · 春季”，不只显示“全文”。

高基数关系不直接灌入普通结果：搜索“木材”先返回木材条目，再提供“查看需要木材制作的内容”；搜索地点或矿井层段可提供带条件的分类浏览入口。应用不做自由自然语言问答，也不回答需要日期、进度或存档的“今天能否买到”“现在在哪里”。

### 一等分类筛选

| 类别 | 首批一等筛选 |
|---|---|
| 商店 | 地点；普通/节日/旅行等出现性质；金币购买/物品兑换 |
| 作物 | 季节；首次成熟天数区间；是否再生；种子获得方式；关键种植要求 |
| 村民 | 常住地点；生日季节；可婚配资格 |
| 大型可制作物 | 加工机器/设施容器/装饰照明/不可制作物；制作或其他获得；解锁阶段 |
| 工具 | 工具类型；升级档位 |
| 怪物 | 出现区域；矿井层段 |
| 鱼类 | 水域；地点；季节；时间段；天气 |
| 武器 | 类型；获得方式；地点/矿井层段；伤害区间 |

价格只在有相应事实的类别开放筛选或排序，并明确区分购买价与出售价格；兑换成本不得进入金币价格范围。材料、商品、掉落物、机器输入输出和人物关系不做超长多选 facet。

一等 facet 是版本化白名单；builder 不因发现任意新字段自动把它变成筛选器。只有语义稳定、可查询、能显著缩小玩家选择且有明确未知行为的维度才可加入。

### 反向浏览白名单

详情可提供以下有明确方向的入口：

- 物品 → 用于哪些配方、被哪些机器处理、由哪些怪物掉落、由哪些商店出售/兑换；
- 配方/大型可制作物 → 制作材料，机器 → 输入与产出；
- 作物种子 ↔ 对应作物，作物 → 种子来源和收获物；
- 怪物 ↔ 掉落物；
- 地点/水域 → 在此出现、可钓或可购买的内容；
- 工具 → 前后升级档位；
- 武器 → 商店、掉落、宝箱或奖励来源；
- 人物 → 有证据的有向人物关系。

入口用“用于制作”“由这些怪物掉落”等方向性文案，不能统称“相关内容”。反向查询只表示从已发布有向关系索引反查，不创造反向事实；人物关系仍要求另一条证据边或已验证互逆规则才能改变称谓。

### Facet 原子性与组合语义

- 同一 facet family 多选为 **OR**；不同 family 之间为 **AND**。
- 只提供正向筛选，不提供容易把未知当成否定的 NOT 筛选。
- 每个 facet 原子关联稳定的 `scope_family + scope_id`。地点、季节、时间、天气、价格和条件若描述同一报价、捕获、出现或获得规则，必须在同一 scope 内联合匹配；不能从不同规则拼出不存在的答案。
- `scope_id` 使用稳定事实项、报价、捕获、掉落或升级规则 ID，不用数组序号、中文值或内容哈希。
- `fixed` 和具有可靠静态适用范围的 `conditional` 可生成 facet；命中条件事实时卡片显示条件摘要。
- `dynamic_rule` 只有存在可靠静态边界时可生成该边界的 facet，不能求值为玩家当前结果。
- `unknown`、`not_collected`、`not_applicable` 只记录 facet group 状态，不生成具体 facet 值；选择具体值时不命中，但实体保留在未筛选的“全部”。
- 部分识别或不透明条件不能参与“当前可买、当前可钓、现在出现”等布尔判断，也不能静默丢失未知子句。
- `false`、`0` 在契约中是合法已知值时仍是值，不自动转为缺失状态。

`browse_facets` 至少能区分 entity、facet key、scope family/id、值类型及单值/区间、单位、claim 状态、条件集合和条件完整性；每种值类型只能填充对应值列。facet group 单独保存每个实体在该维度的状态，避免缺少子值被解释成未知。

### 排序、分页和性能

- 有搜索词默认相关性；无搜索词默认稳定中文名称。
- 类别按契约开放有限排序：购买价、出售价格、成熟天数、伤害或矿井层段；不提供“热门”“推荐”“最赚钱”等无证据排序。
- 相关性采用版本化 match tier；同层按规范名称排序，最终以实体类型和稳定实体 ID 兜底。数值排序也必须以稳定实体 ID 兜底。
- 查询在数据库中完成候选、筛选、排序和游标分页；不得先从各通道任取固定 60 条再在内存合并，也不得加载整类详情后筛选。
- 游标绑定数据包摘要、规范搜索词、筛选 hash、排序契约版本和最后 rank tuple/实体 ID。切包、改搜索、改 facet 或改排序后旧游标失效。
- schema 5 为名称/拼音/别名前缀、实体类型组合、facet 文本和数值区间、关系双向查询及稳定排序建立索引；实现以真实查询计划和数据规模验证。

### 移动端渐进展开与结果状态

- 分类页首行只显示当前类别最常用的 2–4 个 facet；其余进入“更多筛选”。
- 已选条件始终以可单独移除的标签显示，并提供“清除全部”；筛选入口显示已选数量。
- 搜索和浏览结果统一使用决策 10 的行动摘要卡；条件命中同时显示紧邻的限制说明和命中原因。
- 结果、数量、查询文本、facet 和排序必须属于同一个已完成查询快照。新查询加载时显示明确进度或继续标记旧快照，不能把旧结果归到新条件下。
- 空结果明确列出生效条件，提供清除全部和逐项移除；可以建议移除最可能限制结果的 facet，但不能假称数据不存在。
- 最近搜索只保存用户实际提交的文本，不记录筛选浏览、反向关系跳转或输入过程。

### 验收任务

至少证明以下任务无需查看技术字段即可完成：

- 找到春季可种且成熟较快的作物；
- 找到河流、春季、雨天可钓的鱼，并确认这些条件来自同一捕获规则；
- 按地点找到商店并区分金币购买和物品兑换；
- 从木材反查需要它的制作内容；
- 从掉落物反查来源怪物，再查看其出现区域/层段；
- 找到某档工具及其前后升级关系；
- 按武器伤害和获得方式缩小范围；
- 查看文森特或贾斯的有向亲友关联而不产生恋爱或自动镜像结论。

同时覆盖：同维度 OR、跨维度 AND、同 scope 联合条件、未知/暂未收录保留在“全部”、条件命中提示、空结果恢复、稳定分页无重复/遗漏、切包后游标失效，以及查询过程中不短暂展示错配结果。

### 范围边界

本项决定查询语义、入口分工、facet 白名单、反向浏览方向、组合规则和稳定分页，不锁定物理表列名、具体 SQL、最终控件样式、每页数量或性能阈值。质量阈值和真实包验收归决策 12，实施切片归决策 13。

## 依据

- 用户在 2026-08-13 接受全局搜索边界、一等分类筛选、反向浏览、组合/条件规则、排序分页和移动端结果状态六组提案。
- [玩家问题矩阵](01-player-question-matrix.md)、[玩家语义词汇表](03-player-semantics.md)和[分类信息契约](04-category-information-contracts.md)已把地点、季节、时间、价格、来源、材料和关系定义为玩家行动问题；[跨仓库数据契约](09-cross-repo-data-contract.md)已预留规范事实、关系、`entity_cards`、`browse_facets` 与双向索引；[玩家信息层级原型](10-information-hierarchy-prototype.md)已规定行动摘要和渐进展开。
- 当前 `SearchRepository` 支持名称、拼音、首字母、别名和 FTS，但每个通道先取固定 60 条、最终排序没有实体 ID 兜底；不能证明稳定分页或完整候选。
- 当前搜索框承诺“名称、地点或用途”，但 schema 4 没有稳定的地点/用途索引或命中原因契约。
- 当前 `CatalogueQuery` 只有一个 `entryCategory` 字符串，`filterEntries` 在内存中按标题和单值分类过滤，不能表达多 facet、区间、scope 原子性或数据库分页。
- 当前搜索和分类页在查询变化时可能暂留旧结果，因此新 query/chip 与旧结果短暂错配；查询快照规则用于禁止这种误导。
- 三路独立只读审查分别从玩家任务、schema 5 查询契约和移动端对抗场景验证了该模型；一致认为高基数关系应反向浏览、小稳定维度应 facet、条件组合必须绑定同一规则 scope。
