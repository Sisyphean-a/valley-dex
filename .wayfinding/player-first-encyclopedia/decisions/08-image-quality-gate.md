# 图片质量门槛

## 问题

发布包应以哪些逐实体和逐分类检查证明图片完整、裁切正确、可辨识且占位只用于官方确无图片的实体，而不是让商店等页面大面积退化为占位？

## 答案

### 逐实体视觉状态

每个发布实体必须明确属于一种视觉状态：

- **自身官方图片**：实体具有自己的官方视觉，必须正确物化。
- **声明的官方复用**：继承或复用另一官方实体的图片，必须记录来源实体、官方资源和复用理由。
- **官方无实体图片**：经证据确认不存在适用的实体视觉。
- **展示代理视觉**：应用使用店主头像、关联人物视觉或类型语义图标帮助识别，但不计作该实体自身官方图片。
- **待人工复核**：自动检查发现潜在错图、错帧、异常裁切或重复；复核完成前不得发布。

空 `image_path`、`imageRequired=false` 或可选图片全透明都不能自动证明“官方无图”。发布图片不得是通用占位 WebP。

### 自动逐实体门禁

每张发布图片必须满足：

- 实际官方来源唯一且可定位；规范化文件名发生碰撞时拒绝静默选择。
- 图集、portrait、sprite 和独立纹理使用已登记且有版本的视觉规则；图集型来源缺少确定裁切规则时不得把整张图缩成实体图片。
- 裁切矩形为正、未越界，图片可解码为真实无损 WebP，尺寸有效且不是全透明。
- manifest 或同等发布清单把实体 ID、图片路径、SHA-256、实际来源、裁切矩形、视觉规则版本及复用关系绑定在一起。
- 独立打包时重新校验文件格式、解码、尺寸、透明度和哈希，不只检查路径、扩展名与存在性。

### 分类覆盖

每个实体分类必须明确采用以下策略之一：

- **全部必需**：分类内所有应有图片的实体均达到 100%。
- **按名单必需**：明确列出应有图片的实体，名单内达到 100%，其他实体逐条声明合法状态。
- **展示代理视觉**：该类在应用中使用有明确语义的代理视觉。
- **整类不适用**：分类契约确认该类没有实体图片意义。

图片丰富的玩家实体类别不设低于 100% 的缺图容错；例外逐实体说明，不能用总体百分比掩盖。商店明确采用店主头像或店铺性质图标作为展示代理，不伪造店铺官方图片。技术支援记录可复用被聚合人物的展示视觉，但不能冒充自身实体图片。

### 视觉正确性复核

builder 为真实发布包生成确定性联系表和异常清单，至少包含：

- 新增图片及视觉规则变化涉及的全部图片；
- 新游戏版本中来源、裁切、规则或哈希发生变化的图片；
- 极小主体、极端比例、异常透明占比和可疑触边裁切；
- 相同或近似重复图片；
- 跨实体、跨分类复用；
- 每个分类的固定代表样本。

自动异常只是复核候选，不直接证明错误；每项必须形成“确认正确”或“需要修复”的可追踪结论。存在未处理的待人工复核项时阻断 `.svdata`。具体样本数量、异常阈值、复核频率和真实设备截图证据留给决策 12。

### App 状态与占位

App 必须区分：

- 官方无图；
- 合法展示代理；
- 数据包缺图；
- 文件损坏或解码失败。

前两种使用本地语义图标、色块或合法代理视觉；后两种属于数据包异常，不能退化成普通“暂无图片”。数据管理页提供图片健康状态；列表、详情和关系卡必须采用一致状态，同一分类大量异常占位应被验收发现。

### 发布报告

报告至少按分类输出 `total`、各视觉状态数量、必需数、物化数、缺失数、解码失败、全透明、非法裁切、待复核和已确认复用，并提供逐实体诊断清单。具体 schema 和 manifest 字段由决策 09确定，包级覆盖阈值与验收证据由决策 12确定。

### 语义所有权

- builder 的 `context:offline-official-data` 拥有实体视觉状态、视觉规则、物化、内容绑定、异常复核和发布阻断。
- app 的 `context:offline-encyclopedia` 拥有官方无图、代理视觉和包异常的玩家化表达，不重新解释图片来源。

## 依据

- 用户在 2026-08-13 对逐实体视觉状态、自动门禁、分类覆盖、视觉复核和 App 图片状态确认“全部接受”。
- 当前真实包游戏版本 `1.6.15.24356` 的全局必需图片为 `1031/1031`，但数据库逐类统计仍有 `drop 287/298`、`villager_gift 34/39`、`object 804/807`，证明只统计 `imageRequired` 不能解释全分类缺口。
- 当前 builder 已能拒绝缺少来源、资源不存在、越界、解码失败和必需图片全透明，并生成最大 96×96 的无损 WebP；但包级完整性只检查路径、后缀和存在性。
- 当前自动检查不能证明正确实体、正确帧、主体可辨识或重复合理；历史上实际发生过 Abigail 整张头像表、工具错 sprite、作物透明格和家具错误矩形。
- 当前真实产物存在大量重复哈希；部分复用合法，例如官方共用图标，因此必须采用声明复用和人工复核，而不是简单禁止重复。
- 当前 App `EntryImage` 只有 `Packaged`/`Missing` 两态，图片加载失败与官方无图共用同一占位；安装校验虽检查图片可解码、尺寸和透明度，已激活包与 UI 状态仍不能表达异常原因。
