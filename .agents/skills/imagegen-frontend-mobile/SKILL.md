# 高端移动 App 图像

只交付移动屏幕图或流程图，不进入 SwiftUI、React Native、Flutter、HTML 或实现说明。先读[视觉质量共用规则](../references/visual-quality.md)，其中“网页”表述在本技能中按移动 App 屏幕理解。

默认倾向：高艺术指导、低密度、强平台感、强一致性、可读文字、受控色板、丰富但克制的图像与纹理。用户语境覆盖默认值。

## 1. 锁定平台与设计圣经

先选一种平台模式并贯穿全套：

- **iOS 原生高端**：克制 chrome、清晰 safe area/tab bar、优雅间距、自然 sheet；
- **Android 原生高端**：明确 app bar、Material 式组件节奏、bottom navigation、状态与 sheet 逻辑；
- **跨平台中性高端**：通用导航、清楚层级，减少平台专属装饰。

随后根据产品内容选择主艺术方向，并锁定“设计圣经”：设备与画布比例、色板、字体角色与字号节奏、间距、圆角、图标、图片/插画、纹理、导航模型、按钮、卡片/列表、阴影和装饰资产。不得在同一套图中混用 iOS 与 Android 习惯。

**完成标准：已写出平台模式与设计圣经清单；每个后续屏幕都能逐项沿用同一产品身份，同时允许构图和节奏变化。**

## 2. 定义真实流程

根据任务确定屏幕数和顺序。用户要几屏就至少生成几屏；onboarding、auth 或完整概念应覆盖必要状态，而不是用一个漂亮主页代替流程。每一屏都要能回答它从哪里来、用户做什么、下一屏为何出现，例如 onboarding → 权限 → 个性化首页，或浏览 → 详情 → 结算 → 成功。

Onboarding 各屏承担不同叙事任务，不复制同一构图换标题。首屏保持最干净：一个主要信息、一个视觉焦点、一个主操作和至多一个次操作，不堆统计卡、标签和说明。

**完成标准：屏幕集合构成可解释的用户旅程，状态连续且没有填充屏。**

## 3. 生成与再生成

直接生成足量、清晰、独立的屏幕图。文字或组件太小时，生成新的独立屏或细节图；不得从旧拼图裁切、放大或切片。再生成需保持设计圣经，只修正清晰度、层级、比例、间距或弱构图。

默认把每屏放在细致、克制的手机框中：iOS/中性概念用 iPhone 风格，Android 概念用 Android 风格。全套设备样式、大小、对齐和外边距一致，画布四周平衡；设备框只提供语境，App 内容仍是视觉主角。用户明确要求 raw screen 时才去框。

**完成标准：每屏在正常查看尺寸下可读，设备展示一致；不清楚的屏已重新生成而非裁切。**

## 4. 移动原生规则

尊重 status bar、顶部标题区、safe area、bottom navigation、home indicator、手势区和 sheet 停靠区；关键内容与触控不得进入危险区域。导航模型需稳定，tab、返回、层级和当前状态可理解，屏幕不能像缩窄的网站。

文字优先可读：正文、标签、按钮和导航在最终展示尺寸下无需放大；减少装饰性微字，层级靠字号、字重、位置和留白建立。屏幕内容偏多时重组或分屏，不整体缩小。

避免漂浮卡片、药丸、渐变、玻璃和随机彩色状态堆积。允许更丰富的构图，但每一层都必须服务层级或品牌。图片可以作为背景或内容层，但用遮罩、渐变或取景保证文字对比度。图标保持自有感、同一笔画/填充逻辑和明确语义，不默认开发者工具式通用线框图标。

**完成标准：safe area、导航、文字、触控和层级看起来像可运行的真实 App。**

## 5. 艺术指导

按产品内容选择一套主方向，并组合字体、构图、图像、纹理、色板与标志组件。色板使用一个主基底、一个主要强调和少量语义色；不自动使用紫蓝创业渐变，也不随机为每屏换色。

类别只提供约束，不提供模板：

- 金融强调信任、数值清晰和真实状态；
- 健康/健身强调进度、身体信息与鼓励反馈；
- 效率工具强调行动层级和低干扰；
- 社交强调人物、内容与互动关系；
- 商务强调商品媒体、价格与购买路径；
- 生活方式强调氛围图像，但仍保留功能层级。

用纹理、颗粒、材质、遮罩、插画或摄影建立品牌世界，但不要牺牲信息。多屏应“同一系统、不同节奏”：首页、详情、表单、成功态应各有构图目的，不是同一模板换数据。

**完成标准：每种视觉材料都能说明它服务的产品信息或品牌作用，且各屏变化未突破设计圣经。**

## 质量门

交付前逐屏观察并修正：平台模式统一；流程顺序合理；设计圣经贯穿；屏幕数足够；首屏克制；safe area、导航和触控可信；文字正常尺寸可读；色板、图标、纹理和图片有品牌理由；无网站式结构、套卡、伪复杂度或模板漂移；手机框统一且不抢内容；所有弱屏已再生成。只输出最终图像集合，不附代码。
