# 图像先行的网站实现

设计图是视觉事实源，代码是翻译层。可生成图像时，顺序固定为：**生成图像 → 深度分析 → 实现 → 对照验证**。若环境没有图像生成能力，明确告知用户并停止在编码前，除非用户授权改走非图像先行实现。先读[视觉质量共用规则](../references/visual-quality.md)。

默认倾向：高变化、低密度、强艺术指导、强可实现性、充足留白和积极生成图像；用户语境覆盖默认值。

## 1. 定义设计世界

推断网站类型、受众、区块数、主题、背景、字体性格、Hero 架构、区块节奏、四个左右标志性组件、媒体处理和动效语言。组合必须来自项目内容，不套固定暗色居中 Hero 或卡片网格。

Hero 保持单一焦点：短标题、短说明、一个主 CTA 和至多一个次 CTA，首屏在小型笔记本中完整可见。避免微型标签、伪系统状态、信任条和功能清单挤入 Hero。多区块页面应有明显节奏变化，不连续复制左右图文或层层套盒。

**完成标准：已锁定一套贯穿所有图像的色彩、字体、圆角、按钮、媒体和区块语言。**

## 2. 生成足量图像

视觉任务且有生成能力时，必须先生成设计图。默认每个区块一张大而清晰的独立图；区块多就增加图像，不把整站压成文字不可读的长板或九宫格。完整页参考只用于把握总体节奏，不替代区块图。

区块文字、间距、按钮或组件看不清时，为同一设计世界重新生成独立区块图或细节图。保持色彩、字体气质、按钮、圆角、媒体和品牌一致，同时放大待提取信息。不能把旧大图裁剪、放大或切片当新参考，因为裁切会破坏边距、比例和字号关系。

外部网站或用户图片只作为输入参考；最终实现仍以本轮生成并确认的图像系统为准，除非用户明确要求逐像素复刻所给设计。

**完成标准：每个待实现区块都有足够大、可读、无需猜测主要结构的参考；不清楚之处已重新生成。**

## 3. 深度提取

逐张建立实现规格，而不是只描述“氛围”。记录：

- 可读原文、标题行数与换行、CTA 文案；
- 字体角色、相对字号、字重、行高、字距和对齐；
- 容器宽度、栅格、边距、区块间距、内部 padding 和移动端暗示；
- 色板、表面、描边、阴影、圆角、图标和图片处理；
- 按钮层级、尺寸与状态；组件重复规则和区块排序；
- 仍不明确的细节。

先提取 token 和重复模式，再逐区块写结构规格。文字以清晰可读的图像内容为准；无法确认时使用简洁、符合品牌的文案，不编造复杂术语或精确数据。

**完成标准：每个区块的文字、排版、空间、颜色、组件和媒体都能映射到代码；未知项已再生成或显式裁决。**

## 4. 忠实实现

先建立全局 token、容器、字体和响应式规则，再按图像顺序实现。把视觉上的关系翻译成可维护布局，不把独特构图简化成通用模板，也不为了复用强行把不同区块合并为一种组件。

固定媒体框的比例、焦点和 `object-fit`，不要让运行时图片尺寸改变布局。Hero、导航和 CTA 在常见小型笔记本首屏中仍清晰；窄屏重新编排而非等比缩小。保留图像中的留白、字体张力、视觉重点和标志性组件，同时实现焦点、hover、active、loading、empty 和 error 等真实状态。

缺失细节按顺序解决：重新生成 → 从已锁定设计系统推导 → 选择最少、最一致的实现。不得用方便的默认组件填空。

**完成标准：实现仍能一眼认作同一网站，且代码结构、资源和交互真实可运行。**

## 5. 对照验证

在目标桌面尺寸和窄屏实际渲染，逐区块与参考并排检查：

1. 构图、容器和视觉重心；
2. 标题换行、字号关系和文字密度；
3. 间距、媒体裁切、按钮与圆角；
4. 色彩、阴影、纹理和标志性细节；
5. 首屏完整性、响应式重排、状态和动效降级。

发现偏差时修实现；若参考自身不可提取，则回到生成步骤，不靠猜测补齐。

## 交付门

图像确实先于代码生成，或缺少生成能力且用户已明确授权改走普通实现；区块数与参考数足以清晰提取；所有补图均为新生成而非裁切；已形成并应用设计规格；Hero 简洁且小屏首屏可见；无套盒、卡片泛滥、微 UI 噪声或重复区块模板；文本、排版、间距、按钮、色彩和媒体均经过对照；最终桌面与移动端产物已观察。全部成立才算完成。
